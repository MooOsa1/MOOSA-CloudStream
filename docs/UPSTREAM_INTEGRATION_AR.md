# دمج CineStream وStreamPlay: حالة العمل وحدوده

## المنفذ في هذه المرحلة (v132)

- إضافة متابعة يومية لإصدارات المصدرين مع تثبيت إصدار ورقم SHA-256 للمخرجات، ورقم commit للمصدر، والتحقق من وجود ملفات Kotlin/Java الأصلية.
- عند اكتشاف تغيير، GitHub Actions يفتح **Pull Request للمراجعة** للبيانات الوصفية فقط. **لا** ينزّل ملفات CS3 ولا يشغّلها ولا يدمج أكوادًا غير مختبرة ولا ينشر تحديثًا تلقائيًا.
- توسعة رصد CineStream وStreamPlay المثبّتين في محرك MOOSA Hub: إذا كانا مسجّلين في قائمة CloudStream العامة لكن ليسا في القائمة الاعتيادية، يمكن العثور عليهما للأفلام والمسلسلات أيضًا. يظل هذا الاعتماد على **وجود الإضافتين مثبّتتين ومفعّلتين**.
- الإضافتان المنشورتان من هذا المستودع لا تزالان **MOOSA Hub وMOOSA Arabic فقط**. لا تُنسخ مصادر جديدة ولا تُحذف المصادر القديمة.
- تشغيل التورنت خارج نطاق خطة الدمج. يستمر فلتر 720p+ وتحقق هوية العمل/الحلقة وفحص روابط MOOSA الحالي؛ وهذا لا يضمن بثًا بلا تقطيع.

## ما لم ينجز بعد

**لم يصبح CineStream ولا StreamPlay محركين مدمجين مستقلين داخل MOOSA Hub.** دمج المحركات يتطلب نقل الكود القابل للبناء، ضبط اعتمادياته، تدقيق سلامة الهوية والجودة، ومعالجة الرخص ثم اختبار تشغيل فعلي على Fire TV. فتح PR للبيانات الوصفية لا يحدّث مشغل الفيديو.

- CineStream: المشروع المصدر [SaurabhKaperwan/CSX](https://github.com/SaurabhKaperwan/CSX) يوفّر كود Kotlin، لكنه يعلن توقف الصيانة مؤقتًا. الكود يعتمد على ملفات إعداد ومفاتيح API لـ SIMKL وTMDB وغيرها، وعلى حزم ومواقع كثيرة قد تتغيّر. وصف الرخصة في README هو GPLv3 أو أحدث، لذا النسخ والتوزيع يستلزمان الالتزام بشروطها مع الإسناد ومصدر الأجزاء المنقولة.
- StreamPlay: [phisher98/cloudstream-extensions-phisher](https://github.com/phisher98/cloudstream-extensions-phisher) ينشر ملف StreamPlay.cs3 في فرع builds، لكن فرع master الذي تم فحصه لا يحوي ملفات المصدر الخاصة به. ملف CS3 ليس كود المصدر القابل للتحديث. وصف الرخصة في README هو GPLv3 أو أحدث، لكن ذلك **لا يعوّض الحصول على المصدر**.
- لا يجوز نقل إصدار CS3 إلى MOOSA والادعاء أنه صار محرك Kotlin مستقلًا قابلًا للتحديث. يجب الحصول على مصدر StreamPlay القابل للبناء أو إيجاد بديل ذي مصدر متاح.
- ما يزال التحديث التلقائي لكود المصدر **غير مفعّل**. الفحص المؤتمت يكتشف تغيير إصدار/هاش المصدر، ولا يضمن صلاحية الروابط أو إصلاح موقع متوقف.

## كيف تعمل المراقبة

المهام: `.github/workflows/watch-upstream-plugins.yml`، الساعة **04:17 UTC يوميًا** أو يدويًا من GitHub Actions.

1. تُجرى اختبارات آمنة دون شبكة لـ `scripts/monitor_upstream_plugins.py`.
2. تُقرأ قائمتا builds/plugins.json من المستودعين الموثوقين حصريًا، ويُتحقق من معرّف CineStream وStreamPlay الدقيق، وتطابق عنوان CS3، ورقم الإصدار والحجم و SHA-256.
3. يُقرأ Git commit الحالي وشجرة ملفات Kotlin/Java. إذا تعذر الفحص تتوقف المهمة بخطأ بدل تسجيل «مصدر سليم» من التخمين.
4. عند التغيير يُنشأ PR لتحديث `.github/upstreams.lock.json` فقط. الدمج والتطوير والنشر يحتاج اختبار ومراجعة منفصلة.
5. إن منعت إعدادات المستودع إنشاء Pull Requests بواسطة GitHub Actions فالمهمة ستسجل فشلًا واضحًا؛ يلزم تفعيل صلاحية **Allow GitHub Actions to create and approve pull requests** في إعدادات المستودع.

## الشروط قبل بدء دمج المحركات

1. مصدر متاح + توافق مع رخصة GPL + عدم نشر مفاتيح/API secrets.
2. مصادر HTTP المباشرة فقط (لا تورنت)، 720p على الأقل، واسم فيلم وحلقة وموسم مطابق.
3. مهلات وفحص موزع عادل وعدم تضخيم الضغط على Fire TV.
4. اختبارات Kotlin والبناء بلا أخطاء، ثم تجربة تشغيل حقيقة على جهاز Fire TV، وألا تزيل الترقية السيرفرات الصحيحة القديمة.
5. مصدر منفصل يمكن تعطيله بسرعة عند حدوث تعطل، مع تشخيص واضح.

**المهم:** هذه مرحلة تأسيس حقيقية للمراقبة والتوافق مع الإضافات المثبتة، **وليست اكتمال دمج المصدرين داخليًا بعد**.

## المرحلة الثانية — v133: أول مصدر مدمج فعليًا (VaPlayer)

- **VaPlayer (من CineStream):** مدمج الآن داخل MOOSA Hub كمصدر HTTP/HLS مستقل. لا يحتاج ملف CineStream.cs3 ولا يتطلب تثبيت CineStream في CloudStream. هذا ليس نقل CineStream بأكمله، وإنما تكامل أصلي بمصدر واحد ضمن محركاته.
- **تجربة المصدر:** افتح MOOSA Hub → Settings → Providers → Manage Providers وابحث عن `MOOSA CineStream • VaPlayer`، تأكد أنه Enabled واختبره. Source Tester يستخدم IMDb لفيلم Inception كنموذج فقط؛ قد يرجع UNVERIFIED إذا كان الاستضافة محجوبة أو الرابط غير صالح. نجاح فحص الفيديو ليس ضمانًا بثًا متواصلًا.
- **طريقة المطابقة:** IMDb ID للفيلم `tt...` أو IMDb ID للمسلسل مع Season/Episode محددين. لا توجد مطابقة عشوائية بالاسم ولا تورنت.
- **الجودة:** روابط HLS من المصدر تبدأ بجودة Unknown ولا تُعرض إلا بعد قراءة Playlist تثبت 720p أو أعلى. روابط الملفات الأخرى لا تُرفع جودتها بالتخمين.
- **المحافظة على القديم:** بقية المصادر وفحوص الجودة والحظر وفوكس التلفزيون دون تغيير. يمكن تعطيل المصدر من Providers إذا تأخر أو توقف.
- **تنبيه:** هذه النسخة مختبرة بالبناء وUnit tests فقط إلى أن يتم اختبار المحتوى الحقيقي على Fire TV. الوصول إلى API من بيئة CI قد يختلف عن الإنترنت في عُمان، وعنوان VaPlayer أو آلية الوصول قد يتغيران.
- **الإسناد والرخص:** تصميم طلبات VaPlayer مستلهم من مشروع CineStream ذي شروط GPLv3-or-later. أي ملفات مشتقة من كود GPL يجب توزيعها وفق الرخصة مع حقوقها ومصدرها. لا تدمج كود CineStream الكامل أو مفاتيحه السرية دون مراجعة توافق الترخيص ومتطلبات البناء.
- **StreamPlay:** ما زال غير مدمج داخليًا؛ ملف CS3 المنشور وحده ليس بديلًا عن كود المصدر القابل للبناء، والمتابعة اليومية للإصدارات تبقى مراجعة بيانات فقط.
