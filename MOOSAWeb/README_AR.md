# MOOSA Web — النسخة الأولى

موقع مستقل عن إضافة **MOOSA Hub**، بتصميم عربي للكمبيوتر والتلفزيون والجوال، مع مشغل فيديو داخل الموقع.

## ما الذي يعمل؟

- تصفح الأفلام والمسلسلات من TMDB بنتائج حقيقية، مع بحث وتصنيفات وترتيب وبلد إنتاج، **واختيار الموسم والحلقة داخل صفحة المسلسل**.
- صفحة تفاصيل لكل عنوان، وصور وتقييمات، وقائمة «المفضلة» محفوظة على جهازك.
- مشغل HTML5 يدعم MP4 وWebM وHLS عندما يدعم المتصفح وصاحب المصدر ذلك.
- اختيار جودة HLS المتاحة، وترجمات عربية وإنجليزية SRT/VTT، وإضافة ترجمة محلية وتعديل توقيتها ±15 ثانية.
- فيديو تجريبي حر للاختبار، وكذلك فتح فيديو محلي من جهازك.

**مهم:** وجود فيلم في TMDB **ليس دليلًا على توفر رابط تشغيل**. الآن يبدأ الموقع البحث الآلي عن روابط تشغيل قابلة للويب عند الضغط على Play، من محولات مصادر تعمل داخل Render، **بدون إقران جهاز أو تشغيل CloudStream**. إضافات CloudStream المكتوبة لأندرويد/Kotlin لا تعمل في Node.js مباشرة، والمستودعات الخارجية تتطلب محولات ويب مستقلة لها.

## تشغيل الموقع على الكمبيوتر

1. ثبت Node.js الإصدار 20 أو أحدث.
2. افتح مجلد `MOOSAWeb` في Terminal.
3. انسخ `.env.example` إلى `.env`.
4. أضف مفتاح TMDB في المتغير `TMDB_API_KEY`، أو استخدم `TMDB_READ_ACCESS_TOKEN`.
5. شغّل:

```bash
node --env-file=.env server.mjs
```

6. افتح `http://localhost:3000`.

**ملاحظة:** الكود لا يحتاج `npm install`. الاختبارات تعمل عبر `npm run check`.

## تشغيل فيلم من مصدر قانوني

يمكنك لصق رابط فيديو آمن `https://...mp4` أو `https://...m3u8` في المشغل. لإضافة مصادر لعنوان معين عدّل `data/streams.json`؛ اسم المفتاح `movie:رقم_TMDB` أو `tv:رقم_TMDB`، ولتشغيل حلقة محددة استخدم `tv:رقم_TMDB:رقم_الموسم:رقم_الحلقة`؛ كل حلقة تتطلب رابطها الخاص حتى ما تنفتح حلقة أخرى بالغلط. يتطلب HLS وترجمات المصدر تفعيل CORS على الخادم. المشغل **لا يتجاوز DRM أو حماية المواقع أو صلاحيات المحتوى**.

## تشغيله على الإنترنت

نحتاج استضافة تدعم **Node.js**، ومتغير بيئة لمفتاح TMDB، ورابط HTTPS. رفع الملفات إلى GitHub **لا ينشر الموقع تلقائيًا**، وGitHub Pages وحده لا يستضيف الخادم الذي يتصل بـTMDB. ملف المشروع منفصل عن CloudStream، وبالتالي تطويره لا يغير الإضافة الحالية.


## نشر نسخة MOOSA Web على Render

تم تجهيز ملف `render.yaml` في جذر المستودع، وهو يحدد تشغيل الموقع مستقلاً عن إضافة CloudStream.

1. افتح [لوحة Render](https://dashboard.render.com/) وسجل الدخول.
2. اختر **New → Blueprint** واربط حساب GitHub بمستودع `MooOsa1/MOOSA-CloudStream`.
3. اختر ملف `render.yaml` في الفرع `main`، ثم أدخل مفتاح `TMDB_API_KEY` في خانة المتغير السري عندما يطلبه Render.
4. نفّذ **Apply / Deploy**. سيظهر رابط الموقع في صفحة الخدمة بعد نجاح النشر؛ اختبر المسار `/healthz` للتحقق من عمل الخادم.
5. يتم فحص JavaScript واختبارات الخادم تلقائيًا عند تحديث ملفات الموقع عبر GitHub Actions، وكذلك ضمن أمر بناء Render.

**حدود الخدمة المجانية:** Render يوقف خادم Node المجاني بعد 15 دقيقة من عدم النشاط؛ لذلك قد يستغرق أول فتح لاحق قرابة دقيقة. لمن يريد استجابة سريعة دائمًا، استخدم خطة تشغيل لا تتوقف عند الخمول. لم يتم إنشاء خدمة Render أو حجز دومين أو نشر رابط عام تلقائيًا.

**تنبيه:** مفتاح TMDB يضيف بيانات الأفلام والمسلسلات، لكنه لا يضيف سيرفرات مشاهدة. أضف فقط مصادر التشغيل التي تملك صلاحية استخدامها، مع التأكد من HTTPS وCORS ودعم المتصفح.


## إزالة الجسر القديم من MOOSA Hub

اعتبارًا من MOOSA Hub v127، أُزيلت ميزة Web Bridge القديمة من الإضافة. الموقع يعتمد على مصادر ويب مستقلة ولا يحتاج إلى إقران CloudStream.

## مصادر التشغيل التلقائية المستقلة — بدون إقران

**المسار الافتراضي الآن:** افتح فيلمًا أو حلقة ثم اضغط **Play**؛ يطلب المتصفح من خادم MOOSA Web في Render البحث بالمعلومات الفعلية للعنوان (معرّف TMDB، معرّف IMDb، الموسم والحلقة). لا يحتاج المشاهد إلى تثبيت CloudStream أو فتحه أو إدخال رمز إقران. يعرض الخادم فقط الروابط ذات جودة معلنة **720p أو أعلى**، ويفصل تطابق الحلقة، ولا ينشئ روابط وهمية.

المحولات الموجودة حاليًا:
- **Internet Archive:** يبحث في المحتوى المفتوح الذي يتطابق عنوانه بدقة، ويطلب بيانات الترخيص للعنصر قبل قبول ملفات فيديو عالية الدقة. وجود عنصر على Archive.org وحده **ليس إثباتًا قانونيًا** للحقوق؛ الفحص يعتمد على تصريح حقوق واضح وصالح.
- **HTTP add-ons (Stremio protocol):** يستطيع خادم الموقع الاستعلام عن إضافات Web HTTP تستقبل معرّف IMDb أو TMDB حسب ما تسمح به بيانات الإضافة، وتُرجع روابط فيديو محتملة. تلك إضافات بروتوكول ويب، **وليست ملفات CloudStream `.cs3`**. لأسباب الأمان لا يقبل الموقع عناوين إضافات حرة من الزائر، بل يحددها مشغّل الخادم ضمن المتغير `WEB_SOURCE_ADDONS` بصيغة JSON، مثل:

  `["https://authorized-addon.example/manifest.json"]`

**التوافق الجديد:** لو كانت إضافة Stremio تعلن `idPrefixes` بقيمة `tmdb` أو `tmdb:` يمكن لـMOOSA استخدام `tmdb:<id>`، مع الحفاظ على رقم الموسم والحلقة للمسلسلات. إضافات IMDb القديمة تظل لها الأولوية. إعلان الدقة أو استجابة HTTP ناجحة **لا يعني أن الفيديو اشتغل**؛ يجب اختبار الفيديو الفعلي في المتصفح. هذا التحسين لا يوفر وحده أفلامًا حديثة ولا يضمن غياب إعلانات مدمجة في الفيديو.

أضف فقط مقدّمي خدمة مرخّصين تثق بهم؛ لا يعني توفر إضافة أن استخدامها قانوني لكل عنوان. لا يستخدم الخادم إعادة بث عامة أو تجاوز حماية DRM/CORS. المشغل قد لا يستطيع تشغيل بعض الروابط، ولو كانت متاحة في تطبيقات أخرى.

**تنبيه عن CloudStream:** ربط كل إضافات CloudStream المثبتة في المستودعات الخارجية تلقائيًا عبر Node.js بدون تطبيق أندرويد **غير ممكن بهذه البنية**. للوصول إلى مصدر CloudStream محدد داخل الموقع دون ربط جهاز، يجب بناء محوّل خادم مستقل له، والتحقق من حقوق التشغيل والتطابق والـHTTPS قبل إضافته. لهذا الخيار السحابي المستقل تغطية أقل من مكتبة CloudStream على أندرويد.

ميزة Web Bridge القديمة محذوفة من MOOSA Hub v127 وليست مطلوبة لتشغيل MOOSA Web.

## CloudStream original repository discovery (التجربة الفنية)

أضفنا مسارًا لقراءة الفهارس الأصلية لمستودعي **CineStream** و**StreamPlay** من خادم MOOSA Web مباشرة، بدون ربط أي جهاز:

`GET /api/cloudstream/repositories`

الرد يعرض الاسم والإصدار ورابط حزمة `.cs3` والبصمة إن توفرت، بالإضافة إلى الحالة `indexed` أو `unavailable`. **`indexed` تعني أن الإضافة موجودة في المستودع فقط؛ لا تعني أنها تعمل في المتصفح أو أن سيرفراتها قابلة للتشغيل.**

محرك تشغيل ملفات أندرويد الأصلية ما زال غير موجود. أضفنا عقد اتصال اختياري لمحرك مستقل مؤمّن عبر `CLOUDSTREAM_RUNTIME_URL` و`CLOUDSTREAM_RUNTIME_TOKEN`، لكنه لا يُفعّل إلا بعد توفير وتشغيل خادم أندرويد متوافق واختبار الاستخراج عمليًا. الوضع الافتراضي `not_configured` آمن ولا يقدم مصادر وهمية.

**اطلع على [CLOUDSTREAM_ENGINE.md](./CLOUDSTREAM_ENGINE.md)** للتفاصيل والاختبارات المطلوبة قبل شراء VPS أو الادعاء بأن CineStream وStreamPlay يشتغلان.
